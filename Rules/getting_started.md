# Getting Started (All Final Week Projects)

This guide captures the shared startup guidance across all project options.

Use this document first, then move into your chosen project specification for project-specific requirements.

For meeting and communication guidance with your instructor as customer, see [customer_management.md](customer_management.md).

## 1. Choose Your Project and Confirm Scope

- Pick one project option as a team.
- Read the full specification for that project.
- Confirm assumptions with your customer.
- Keep scope realistic for the final week: start with core requirements, then add enhancements.

## 2. Technical Setup Checklist

1. Create your project structure.
2. Create your Git repository (per course guidance).
3. Commit and push a skeleton version early.
4. Ensure all team members and instructor have access.
5. Define a minimal first data model (smallest useful fields).

If setup is blocked, contact your instructor early.

## 3. Team Workflow Checklist

1. Agree on delivery approach (for example, backend-first vs parallel backend/frontend).
2. Create an initial task list and assign owners.
3. Prioritize minimal implementation tasks first.
4. Run regular team check-ins and track blockers.
5. Keep design and build work in sync (avoid over-designing before coding).

## 4. Build Strategy (Recommended)

- Start small with a working end-to-end slice.
- Expand incrementally once core flow works.
- Favor clear, simple data models first.
- Use pair programming where useful.
- Emphasize quality over quantity.

## 5. Common Technical Expectations

- Use the technology stack covered in training.
- Use persistent storage (database) for core entities.
- Use Git with good collaboration habits.
- Document your API usage (Swagger/OpenAPI if covered in training).
- Assume no authentication unless your instructor asks for it.

## 6. Presentation Readiness (From Day 1)

Prepare notes as you build so final presentation prep is easy:

- What you built and why.
- Key architecture/data-model decisions.
- Tradeoffs and challenges.
- What you would do next with more time.

## 7. Quick Starter Plan (First 1-2 Days)

1. Day 1: Repo, skeleton app, minimal data model, one working endpoint/feature.
2. Day 2: Complete core flow, basic tests/manual verification, initial UI or API docs.
3. Remaining time: harden core flow, add enhancements, improve demo story.
